Installation and administration guide

This guide covers the self-hosted CodeCanyon edition. Buyers deploy their own source, database, AI provider, and optional payment accounts.

1. Requirements

  • Node.js 22 or a compatible active LTS release
  • pnpm 10
  • PostgreSQL with permission to create tables and indexes
  • A public HTTPS domain for production
  • An OpenAI-compatible API key; a free ChatGPT account is not an API billing account

Optional subscriptions require Stripe and/or PayPal business/developer credentials.

2. Guided installation

  1. Upload and extract the source outside the public web root where possible.
  2. Copy .env.production.example to the environment manager supplied by your host. Do not commit a real .env.
  3. Set DATABASE_URL, BETTER_AUTH_SECRET, APP_ENCRYPTION_KEY, NEXT_PUBLIC_APP_URL, BETTER_AUTH_URL, and INSTALLATION_TOKEN.
  4. Run the commands below.
  5. Open https://your-domain.example/install, complete the administrator, branding, AI, and optional SMTP sections, and submit once.
pnpm install --frozen-lockfile
pnpm db:generate
pnpm exec prisma migrate deploy
pnpm build
pnpm start

The installer locks permanently after success. Vercel and other serverless platforms must use their dashboard or CLI for bootstrap environment values because a running deployment cannot reliably rewrite its own environment.

3. AI provider

Open /admin/settings and enter the base URL, model, and API key. Secret keys are encrypted with APP_ENCRYPTION_KEY and are never returned to the browser. Use “Test AI connection” before inviting users.

Each successful generate, regenerate, or rewrite consumes one AI generation. Failed provider calls release the atomic reservation. Clear, edit, save, and copy do not consume usage.

4. Stripe and PayPal

  1. Start with Stripe test mode and PayPal Sandbox.
  2. Save provider credentials in Admin → Configuration.
  3. Configure webhook URLs as /api/webhooks/stripe and /api/webhooks/paypal.
  4. Copy the returned webhook secret or ID into Configuration.
  5. Open Admin → Plans and synchronize Pro and Agency independently for each provider.
  6. Complete checkout, renewal, failed-payment, cancellation, duplicate-webhook, and out-of-order tests before using live credentials.

Checkout redirects never grant access. Signed webhooks are authoritative. The first release supports monthly USD subscriptions only.

4a. Manual bank transfer

  1. Open Admin → Configuration and complete the Manual bank transfer section.
  2. Set Enable bank transfer to true.
  3. Customers open Dashboard → Plans & Upgrade, read the bank instructions, and submit their transfer reference.
  4. Verify the money independently in the bank account.
  5. Open Admin → Bank transfers and approve or reject the request.

A customer submission never activates paid access. Only an administrator should approve after confirming settled funds. Manual approval grants one month from the approval date.

5. Branding and legal templates

Admin → Configuration controls the product name, company name, contact email, and legal URLs. “ReviewReply AI by Aara Creations” remains the default identity. Privacy and terms pages are templates and must be reviewed for the buyer’s jurisdiction; this product makes no compliance claim.

6. Deployment

Node or VPS

Use a process manager or container, reverse proxy HTTPS to the Node port, apply migrations before restart, and keep daily encrypted database backups.

Vercel

Store environment values in the Vercel project, use external PostgreSQL, run migrations from a controlled release step, and redeploy after changing secrets.

Maintenance

Monitor /api/health, database capacity, failed webhooks, AI quota, and logs. The database-backed limiter needs no separate Redis service for the first release.

7. Security checklist

  • Use unique random authentication, encryption, and installation secrets.
  • Never expose AI keys, payment secrets, or full errors to browsers or support tickets.
  • Restrict database network access and require TLS in production.
  • Keep Node.js and dependencies patched; run lint, tests, build, and a dependency audit before release.
  • Back up before upgrades and test restoration.
  • Do not package demo accounts or production customer data.

8. Upgrade and backup

Follow UPGRADE.md. Back up PostgreSQL, replace source without replacing environment secrets, install from the lockfile, run migrations, build, restart, then verify health and core workflows.

9. Troubleshooting

ProblemCheck
404 routeConfirm the production build completed and the correct URL is open.
Prisma validation errorApply migrations, then regenerate Prisma while no Node process is locking its Windows engine DLL.
AI unavailableTest the provider in Admin, verify API billing or quota, model access, and base URL.
Paid plan not activeCheck signed webhook delivery and failed webhook count; never trust the redirect.
Installer environment incompleteAdd all bootstrap values at the host and redeploy or restart.

When contacting support, include the safe error reference and versions—not credentials.
